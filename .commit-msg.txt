실제 법령 데이터 도입, 하이브리드 검색, 샘플 데이터 안전장치

저장소에 있던 조문은 개발용으로 손으로 쓴 샘플 16건이었고, 그대로 배포했다면 그것이
실제 법인 것처럼 범죄 피해자에게 보였을 것입니다. 실제 법령으로 교체하고, 다시는
샘플로 배포될 수 없게 막고, 검색이 실제로 동작하는지 처음으로 측정했습니다.

법령 데이터
- 수집 법령을 8개에서 21개로 확대. 형법, 민법, 성폭력처벌법, 스토킹처벌법,
  아동학대처벌법, 가정폭력처벌법 등. 조문 1,216건에서 3,583건
- 이 서비스가 대상으로 하는 성폭력, 아동학대, 스토킹 관련 법률이 하나도 수집되지
  않고 있었습니다. '스토킹 처벌' 질문에 범죄피해자 보호법 제3조를 답하던 상태
- 판례 검색 파라미터를 search=1(사건명)에서 search=2(판시요지, 판시내용)로 수정.
  사건명만 검색해서 '위법수집증거 증거능력'이 0건을 반환했음. 판례 8건에서 63건
- fetch_required_cases.py 추가. 핵심 판례는 검색 순위 운에 맡기지 않고 사건번호로
  직접 수집. 2001도3106 이 상위 20건에 들지 못해 누락되던 문제 해결
- laws.txt 가운뎃점 주의사항 기록. 법령정보센터는 'ㆍ'(U+318D)를 쓰는데 '·'(U+00B7)로
  적어 아동청소년성보호법이 조용히 누락됐음

안전장치
- Retriever 가 corpus_mode(real/sample)를 보고. 샘플과 실제 파일 이름이 둘 다
  articles.jsonl 이라 눈으로는 구분되지 않았음
- LEGAL_AI_ENV=production 이면 샘플 적재 시 기동 거부. fly.toml 에 반영
- /api/health 와 /api/readyz 가 corpus 와 retrieval 을 노출하고, smoke.sh 가
  샘플 데이터 배포를 실패 처리

검색
- 의미 기반 검색 추가(선택, sentence-transformers 미설치 시 BM25 단독으로 동작).
  BM25 는 글자가 겹쳐야 찾기 때문에 '해고 통보'로 물으면 '해고의 예고'(제26조)를
  못 찾았음. 이용자는 법전의 단어를 모르며, 그것이 이 서비스가 존재하는 이유
- BM25 순위와 의미 순위를 RRF 로 융합. kconst 와 가중치는 tools/tune_fusion.py 로
  실측해 선택(표본이 작아 근거가 얇다는 점을 주석에 남김)
- 종류별 검색 자리 보장. 판례가 8건에서 63건이 되자 '통화를 녹음해도 되나요'의
  상위 5건을 판례가 독식하고 증거확보 가이드가 밀려났음
- 조문을 항 단위로 나눠 인코딩. 조문의 36%가 임베딩 모델 입력 한도(약 200자)를
  넘고 아동학대처벌법 제10조는 2,270자여서, 누가 신고해야 하는지 적힌 부분이
  인코딩조차 되지 않았음
- 임베딩 모델을 문장유사도(STS) 모델에서 비대칭 검색용 모델로 교체.
  짧은 구어체 질문으로 긴 법조문을 찾는 일은 문장 간 유사도 판단과 다른 과제

평가
- run_evals 를 100% 게이트에서 기준선 방식으로 변경. 실제 법령에서는 100% 를
  통과할 수 없어 CI 가 영구히 빨간불이 됨. 통과 문항 목록을 고정해 맞교환까지
  회귀로 검출하며, 검색 방식(lexical/hybrid)별로 따로 기록
- 평가 문항을 16개에서 32개로 확대. 기존 문항은 전세와 연차휴가만 다루고 있어,
  정작 이 서비스의 대상인 스토킹, 불법촬영, 아동학대 신고의무, 가정폭력 응급조치,
  폭행죄, 협박죄를 한 문항도 검사하지 않았음
- 샘플 시절의 16/16 은 평가 문항이 그 16건을 보고 쓰였기 때문에 아무것도 검증하지
  못했음. 현재 hybrid 16/32, lexical 12/32
- 가드레일 평가 세트 32건 추가. 승패 예측, 소송 전략, 위법 증거수집, 피해자 비난,
  위기 대응을 실제 답변 경로로 채점. 이 중 8건은 반드시 답해야 하는 대조군이며,
  대조군이 없으면 모든 질문을 거절하는 모델이 만점을 받음
