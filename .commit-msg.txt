실제 법령 데이터 도입과 하이브리드 검색, 샘플 데이터 안전장치

저장소에 있던 조문은 개발용으로 손으로 쓴 샘플 16건이었고, 그대로 배포했다면 그것이
실제 법인 것처럼 범죄 피해자에게 보였을 것입니다. 실제 법령으로 교체하고, 다시는
샘플로 배포될 수 없게 막고, 검색이 실제로 동작하는지 처음으로 측정했습니다.

법령 데이터
- 국가법령정보 API 로 8개 법률 조문 1,216건 수집 (형사소송법 시행 2026-07-01)
- 판례 63건 수집. 검색 파라미터를 search=1(사건명)에서 search=2(판시요지, 판시내용)로
  수정. 사건명만 검색하고 있어서 '위법수집증거 증거능력' 이 0건을 반환했음.
  그런 이름을 가진 사건은 없기 때문
- fetch_required_cases.py 추가. 핵심 판례는 검색 순위 운에 맡기지 않고 사건번호로
  직접 수집. 2001도3106 이 검색 상위 20건에 들지 못해 누락되던 문제 해결

안전장치
- Retriever 가 corpus_mode(real/sample)를 보고. 샘플과 실제 파일 이름이 둘 다
  articles.jsonl 이라 눈으로는 구분되지 않았음
- LEGAL_AI_ENV=production 이면 샘플 적재 시 기동 거부. fly.toml 에 반영
- /api/health 와 /api/readyz 가 corpus 를 노출하고 smoke.sh 가 샘플 배포를 실패 처리

검색
- 의미 기반 검색(선택) 추가. BM25 는 글자가 겹쳐야 찾기 때문에 '해고 통보'로 물으면
  '해고의 예고'(제26조)를 못 찾았음. 이용자는 법전의 단어를 모르며, 그것이 이
  서비스가 존재하는 이유. 한국어 문장 임베딩과 BM25 를 RRF 로 융합
- 종류별 검색 자리 보장. 판례가 8건에서 63건이 되자 '통화를 녹음해도 되나요'의
  상위 5건을 판례가 독식하고 증거확보 가이드가 밀려났음. 피해자에게 필요한 것은
  손해배상 판결문이 아니라 무엇을 해도 되는지에 대한 안내
- sentence-transformers 미설치 시 BM25 단독으로 조용히 동작

평가
- run_evals 를 100% 게이트에서 기준선 방식으로 변경. 실제 법령에서는 100% 를 통과할
  수 없어 CI 가 영구히 빨간불이 됨. 통과 문항 목록을 고정해 맞교환(한 문항이 붙고
  다른 문항이 깨지는 경우)까지 회귀로 검출. 현재 13/16
- 샘플 시절의 16/16 은 평가 문항이 그 16건을 보고 쓰였기 때문에 아무것도 검증하지
  못했음
- 가드레일 평가 세트 32건 추가. 승패 예측, 소송 전략, 위법 증거수집, 피해자 비난,
  위기 대응을 실제 답변 경로로 채점. 이 중 8건은 반드시 답해야 하는 대조군이며,
  대조군이 없으면 모든 질문을 거절하는 모델이 만점을 받음

문서

  macOS 에는 python 이 없어 빠른 시작 명령이 전부 실패하던 상태였음
